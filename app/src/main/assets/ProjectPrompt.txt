# プロジェクト概要 & アーキテクチャ方針

このプロジェクトは、Java/Kotlin をベースに、HTMX による軽量なフロントエンド部分更新、および Rhino による JVM 内メモリ上での JavaScript 動的評価を組み合わせて構築する Web アプリケーションです。
外部モジュールや重いフレームワークへの依存を極力排除し、シンプル・軽量・高速な自前実装と自己修復（エラーハンドリングによる段階的改善）を基本スタンスとします。

---

# 1. 基本方針 & 開発スタンス

1. **モジュール・ライブラリの厳選（引き算の設計）**
   - 新たな外部ライブラリ（テンプレートエンジンや重いフレームワーク等）の導入提案は避け、言語（Java/Kotlin）の標準機能および軽量な自前実装を優先してください。
   - 不要な抽象化レイヤーを増やさず、コードの透過性と構造のシンプルさを重視します。

2. **自前実装 + エラー自己修復**
   - 堅牢な共通基盤を作るのではなく、まずは最小限の実装で動かし、発生したエラーや例外を検知・修正していくアプローチを前提とします。

3. **メモリ内完結による超軽量化**
   - Rhino は Node.js 等の外部プロセスとしてではなく、JVM の同一メモリ上で直接 JS を評価・実行するために採用しています。プロセス間通信（IPC）や無駄なオーバーヘッドを発生させないコード記述を徹底してください。

---

# 2. 技術スタンス・コード実装規約

### 【フロントエンド / HTML】
- **HTMX 優先**: レスポンスは基本的に HTMX が要求する「HTML の断片（Fragment）」を返却する設計とします。
- **HTML 生成**: Java 15+ のテキストブロック（`"""`）や Kotlin の Raw String / HTML DSL などを活用し、自前でクリアに生成します。
- **XSS 対策の徹底**: テンプレートエンジンを使わないため、ユーザー入力値の HTML エスケープ漏れには厳重に注意し、必要な箇所ではエスケープ関数を適用してください。

### 【バックエンド / スクリプト（Java/Kotlin + Rhino）】
- **役割の明確な分離**:
  - **Rhino**: スクリプトの動的評価・ロジック計算など「純粋な評価（入力 $\rightarrow$ 出力）」に専念させます。
  - **Java/Kotlin**: データハンドリング、HTTP リクエスト制御、最終的な HTML 断片の組み立てを担います。
- **Rhino 実行の安全化**:
  - `Context` や `Scriptable` の生成・破棄、スレッド安全な扱い（ThreadLocal やコンテキスト管理）を意識したコードを記述してください。
  - ES6 以降のモダンな JS 構文が Rhino のバージョンによって動かないリスクに留意し、Rhino が安全に評価できる安全な JS コードを出力・提案してください。
- **堅牢な例外キャッチ**:
  - Rhino 実行時の JS 例外（`RhinoException` 等）は Java/Kotlin 側の境界で確実に補捉し、デバッグしやすい形式でログ出力・レスポンス化する実装にしてください。
